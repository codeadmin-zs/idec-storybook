## Why a design system?

Fleet platforms like **My Garage** ship dozens of screens — tracker tables, map views, filter drawers,
vehicle cards, KPI bars, and product profile pages. Without a system, every team reinvents spacing,
colors, and interaction patterns. Interfaces drift apart, accessibility suffers, and simple changes
become expensive.

A design system solves this the same way **Material Design** and **IBM Carbon** do for their
ecosystems: it turns repeated product decisions into **reusable foundations** (tokens) and
**ready-made building blocks** (components) so teams can focus on fleet logic, not button styles.

## Design principles

These principles guide every token and component in the library:

1. **Clarity over decoration** — Data-dense fleet UIs prioritize readable tables, clear status colors,
   and obvious actions (filters, CTAs, side-rail icons).
2. **Production fidelity** — Components are modeled on real My Garage screens: Tracker summary tabs,
   Criteria filter drawers, product profile cards, and KPI status bars.
3. **Token-first styling** — Visual properties live in <code>@mygarage/design-tokens</code> as
   <code>--mg-*</code> CSS variables. Components consume tokens; they do not hard-code brand values.
4. **Composable layouts** — Primitives combine into patterns: <code>AppShell</code> + <code>SideNav</code> +
   <code>DataTable</code> + <code>FilterDrawer</code> for a full tracker page.
5. **Accessible by default** — Semantic HTML, keyboard support, and WCAG-oriented checks in Storybook.

## What's in the system?

The design system is made of **three layers**. Each layer has a different job — you typically use
all three together in a React app.

## Who is this for?

- **Developers** — Install packages, import styles once, compose components. See the
  **[Developer Guide](./?path=/docs/my-garage-design-system-developer-guide--docs)** for setup,
  theming, and composition patterns.
- **Designers** — Use tokens and Storybook stories as the canonical reference when specifying
  new fleet screens.
- **Product & engineering leads** — A single catalog of what exists, reducing duplicate work
  across squads.
